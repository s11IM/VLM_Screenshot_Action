**中文** | [English](README.en.md)

一个轻量级的视觉语言模型（VLM）截图操作工具：框选屏幕区域，AI 通过截图理解画面，用归一化坐标驱动键鼠，循环执行直到任务完成。无需目标软件提供任何 API 或无障碍接口。


## 设计决策与取舍

### 1. 纯视觉 + 归一化坐标，而不是 UIA / DOM / 无障碍 API

- **得到**：跨软件通用——游戏、模拟器、老软件一视同仁，不依赖目标程序暴露任何接口
- **代价**：定位精度受模型视觉能力限制（小按钮、低对比度 UI 会难），无法操作更高权限（UAC）程序
- **归一化坐标空间**：模型统一在 0–1000 的相对平面上定位（左上 `0,0`，右下 `1000,1000`），与分辨率、窗口大小、DPI 解耦

### 2. 滚动上下文 + 单帧发送，而不是累积全部截图

- **问题**：截图 token 成本高，逐轮累积很快撑爆上下文窗口和预算
- **做法**：仅保留最近 N 个「观察-操作」循环（`contextCycles`，1–999 可调）；每次请求只携带最新一张截图，历史截图替换为 `[IMAGE frame=OMITTED]` 占位符——token 消耗不随轮数累积
- **补偿**：滚出窗口的信息不直接丢弃——活跃任务（`ACTIVE_TASK`）与上一轮总结（`LAST_ROUND_SUMMARY`）以文本锚点保留，长任务不迷失目标
- **代价**：模型失去远期视觉记忆，只能靠文本锚点回溯；需要「回看很久之前画面」的任务不适用

### 3. 每步强制 analysis，而不是只回工具调用

每次工具调用都要求附带 ≤1000 字符的 `analysis`（本步依据）。它同时服务两个目的：决策留痕（可审计、可调试），以及滚动上下文滚出窗口后的摘要素材——第 2 条的文本锚点正是从这里提炼。

### 4. 每步自校准，闭合反馈环

截图上叠加红色十字 / 拖拽轨迹标记上一次落点。模型从「预期落点 vs 实际画面变化」的偏差中自我修正，补偿纯视觉定位的漂移——这是第 1 条取舍的缓解措施。

### 5. 安全边界作为一等设计

| 机制 | 作用 |
|------|------|
| F8 全局急停 | 键盘输入与画面观察期间按住 F8 立即中断，中断后锁存不自动恢复；其余阶段（网络请求、完全自动间隔、点击拖拽悬停）请用界面上的停止按钮 |
| 键盘安全锁 | frameId、截图区域、前台窗口三者与最近一次截图完全一致才允许键盘操作；截图超 5 分钟或前台窗口变化即安全中断 |
| 窗口自动避让 | 截图与操作前主窗口自动隐藏，不遮挡画面、不抢焦点 |
| 脱敏日志 | JSONL 日志按字段名脱敏 API Key、截图 base64 与对话文本等敏感字段（`[redacted]`），2MB 自动轮转 ×4；脱敏按名单匹配，不保证覆盖任意错误字符串，分享前请自行检查 |
| 取消传播 | 中断级联取消 API 请求、键鼠动作与挂机定时器，组合键按逆序释放 |

详见 [SECURITY.md](SECURITY.md)。

### 6. Tauri 单体 + 依赖克制

当前约 6,800 行源码（TypeScript ≈ 3,200 + Rust ≈ 3,600），无 Electron / Node.js 运行时捆绑，产物为标准 NSIS 安装包。前端仅 React + lucide 图标，Rust 侧 enigo + xcap + reqwest，无框架级抽象层——核心逻辑一览无余，方便阅读与移植。

### 工具协议

7 个 OpenAI function-calling 工具（click / drag / hover / keyboard_type / keyboard_press / wait / end_round）；对模型意外返回的 Anthropic `computer` 工具调用自动安全映射（坐标从像素换算为 0–1000，不可安全映射的动作直接拒绝）。

## 架构

### 核心流程

```mermaid
flowchart TD
    A([你先手动截一张图，写下任务再发送<br/>开了完全自动时，到点也会自动截图开始下一轮]) --> B[截取目标区域，连任务一起发给 AI<br/>只带最新一张图，旧的换成一行占位文字]
    B --> C{AI 看图思考：下一步做什么？}
    C -- 回文字，不调工具 --> R[把这轮文字写进对话<br/>本轮到此为止]
    C -- 调 end_round，告诉程序这轮结束 --> R
    C -- 调一个动作工具 --> D{这个工具此刻能执行吗？}
    D -- 「提供模型工具」已关闭，或还没有能用的画面 --> D2[这步没做成<br/>把原因回给 AI]
    D -- 动作不合要求，或执行时出错 --> D3[这步失败了<br/>把原因回给 AI]
    D2 --> I2[立刻补一张新截图，不等待]
    D3 --> I2
    I2 --> I3{连续三次都没做成？}
    I3 -- 是 --> I4([主动结束本轮，把原因写进对话])
    I3 -- 否 --> J
    D -- 能执行 --> E[动手：点击、拖拽、悬停、打字、按键，或 wait 再等一会儿]
    E --> E2[记下动作落点，新截图上用红点标出<br/>打字和按键不标红点]
    E2 --> H{工具后自动截图开着吗？}
    H -- 关着，且这步不是 wait --> H2([本轮停下，等你手动截图])
    H -- 开着 --> I[动作输出后 4 秒内采样校准，不提前触发<br/>解锁后连续确认趋稳；截图后恢复原前台窗口]
    I --> J[新截图成为下一轮的起点]
    J --> C
    R --> K{开了完全自动吗？}
    K -- 开了 --> L[等一段设定间隔，自动截图开始下一轮] --> B
    K -- 没开 --> M([停下，等你下一条指令])
    N[键盘输入或画面观察期间按住 F8：立刻停下<br/>其他阶段用界面上的停止按钮] -.-> C
```

整个程序就是让 AI 反复做「看图 → 动手 → 再看图确认效果」这个循环，直到任务完成或你按停。每一步只把最新一张截图发给模型（旧图换成一行占位文字）来控制成本，内部机制见上面的设计取舍。

图上没有画出来、但代码里确实存在的细节：

- **一次只执行一个动作**。模型偶尔会一口气返回多个工具调用，只有第一个会被执行，其余的直接丢弃。
- **点击前允许一次本地重新定位**。定位后被短暂移开的鼠标会重新移到目标并复查，单击或双击整次调用最多补定位一次，不重放已发出的点击；持续偏移仍报错，拖拽校验不放宽。动作之间移动鼠标或调整本体位置不会因此让下次点击必然失败，但不支持用户和程序同时争用鼠标。
- **红色标记不是操作成功证明**。十字和箭头只按上一次指令的坐标绘制，不是录制的鼠标轨迹。鼠标点击按住 60ms；拖拽依次悬停 100ms、按住 100ms、移动 500ms、终点停留 80ms 再松开，并校验起终点实际鼠标位置。游戏是否接受仍需看新截图，不能只看箭头或“输入已发送”。
- **连续三次做不成，本轮就自动结束**。做不成的步骤（工具被关闭、没有可用画面、参数无效、执行报错）会累计；只要中间成功一次就清零，所以正常流程不会被误伤。没有这道闸之前，模型坚持返回做不成的调用会一直循环下去（`toolFailureGuard.ts`）。
- **失败的步骤不吃等待时间**。未执行和失败的步骤不会启动等待计时器，程序会立刻补一张截图继续问模型（`App.tsx:959-979`）。只有真正执行成功的动作才进入「等画面稳定」，也只有成功的那条路径会清掉早醒存下的剩余时间（`App.tsx:834-835`）。
- **早醒后的 `wait` 从暂停点续上**。等待期间画面先变化再稳定，会提前唤醒并把剩余时间存下来；模型接着选 `wait` 就用这段剩余时间继续等（此时不再探测画面），做别的动作则重新计时（`observationTimer.ts`）。
- **动作输出后有 4 秒校准保护期**。从收到模型的动作输出开始计时（含动作执行耗时），动作完成后立即开始本地采样，但保护期内不能提前唤醒。从这段时间内最平稳的约 1.2 秒多帧窗口估计噪声；保护期不足时使用保守默认值。原有截图截止时间不延长，停止/F8 仍然有效，早醒后续时的 `wait` 仍不探测。
- **解锁后确认连续趋稳，而不是累计三次不动**。采样档位为 `150/250/600ms`，采样耗时计入间隔。使用最长边 320 像素的灰度图，检查至少 4 帧、跨度至少 1.8 秒的像素变化范围、全局均值和最活跃局部块；保护期内的稳定时间不提前抵扣。全局均值上限保持 1.5，局部块和活动像素比例的自适应上限为 60 和 2%，允许校准过的有限局部活动；静态或不足的校准仍使用严格阈值。缓慢累积变化、超限的局部刷新及中间夹杂的明显变化仍会阻止提前触发。一般可在稳定后约 2 秒确认，调度/采集较慢时会更久；证据不足就等到截止时间。画面稳定不等于游戏回合或加载在语义上已经完成。
- **检测忽略本体，截图后恢复原前台状态**。支持时，本体在检测期间保持可见，通过 Windows 采集排除读取其下方画面。最终截图仍短暂隐藏本体；截图和动作结束后，原本在前台的窗口恢复显示、焦点及前后顺序，不永久置顶。后台或最小化窗口不主动抢前台，错误和取消也执行恢复。旧系统或排除失败时退回隐藏检测，并在截图完成后统一恢复。
- **关掉「提前探测」** 就退回纯定时器：睡满设定时间截一张图，不再提前醒来。
- **稳态基线全程评估、小幅更新**。前 4 秒用于初始化，解锁后继续评估完整窗口及最平稳值。只有按旧基线已经合格的稳定窗口，才按 90% 旧值、10% 新值更新下一次噪声参考，更新至少间隔 1.8 秒。当前窗口先判定、后更新，不能靠放宽阈值让自己立即通过；动作前截图不被覆盖，慢变化和明显动画仍会阻止早醒。
- **全新的轮次必须带一张自己的截图，模型才拿得到工具**。可选画面只认 `手动截图` / `完全自动` / 工具执行后这三种来源；从文件上传的图片只作参考，不算可选画面（`model.ts:248-253`）。所以只框选区域、只打字发送的第一轮，程序不提供任何工具，模型只能回文字；等下一轮带上了截图，工具才会出现。
- **请求失败会重试一次**（默认间隔 3 秒），超时按「请求超时」设置（默认 60 秒）。
- **完全没选区域时**：不向模型提供任何工具，模型只能回文字；万一它仍返回工具调用，会被记为未执行，然后直接回到模型（不截图，因为没有区域可截）(`App.tsx:950-953`)。

## 快速开始

### 前置要求

- Windows 10 / 11
- Node.js ≥ 24.12、Rust 稳定版工具链（构建用）
- 任一 OpenAI 兼容接口的 API Key（模型需具备视觉能力）

### 构建

```bash
git clone https://github.com/s11IM/VLM_Screenshot_Action.git
cd VLM_Screenshot_Action
npm ci
npm run tauri dev     # 开发调试
npm run tauri build   # 产出安装包于 src-tauri/target/release/bundle/
```

### 首次使用

1. **配置 API**：右上角齿轮进入设置，填写 API URL、API Key 与模型名
2. **框选区域**：点击「选择截图范围」，在屏幕遮罩上拖动框选目标窗口，Esc 取消
3. **下达任务**：输入框描述目标（如「点击开始按钮并进入设置」）后发送
4. **观察循环**：AI 自动执行 截图 → 分析 → 操作 → 再截图 的闭环，可随时中断；需要挂机时开启「完全自动」并切到迷你模式

## 工具集

| 工具 | 用途 | 关键参数 |
|------|------|----------|
| `click` | 单击 / 双击 | `x, y`（0–1000），`clicks: 1\|2` |
| `drag` | 拖拽 | `fromX, fromY, toX, toY` |
| `hover` | 悬停（等待 tooltip） | `x, y` |
| `keyboard_type` | 输入字面 Unicode 文本 | `text`（≤10000 字符），`intervalMs`，`submit` |
| `keyboard_press` | 物理按键 / 组合键 | `keys[]`（1–8 个），`holdMs` |
| `wait` | 等待画面变化 | 无（不能指定时长） |
| `end_round` | 结束本轮运行 | `message`（给用户的总结） |

## 兼容性说明

- 接口层只依赖 OpenAI 兼容的 `/chat/completions` 格式——OpenAI、通义千问、智谱 GLM、DeepSeek 及各类聚合网关均可直连
- 部分模型（经兼容网关时）会返回 Anthropic 风格的 `computer` 工具调用；适配器会将其安全映射：
  `screenshot→wait`、`left_click/double_click→click`、`mouse_move→hover`、`left_click_drag→drag`、`type→keyboard_type`、`key→keyboard_press`，坐标从像素换算为 0–1000 归一化，不可安全映射的动作会被拒绝
- 多显示器与混合 DPI 已适配（含负坐标副屏）；截图区域必须完整位于同一块显示器内

## 已知限制

1. 仅支持 Windows（输入与前台窗口检测依赖 Win32 API）
2. 无法操作以更高权限运行的程序（UAC 边界）
3. 独占全屏游戏建议改为窗口化 / 无边框
4. 小按钮、低对比度 UI 的定位精度取决于所用模型的视觉能力
5. `keyboard_type` 逐字符发送，不适合超长文本的高速录入
